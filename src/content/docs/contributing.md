title: "Contributing"
---

The most valuable contribution to Pubky is an app people can use. Every new app gives users another reason to own their identity and data, and shows other developers what the protocol makes possible.

## Build an app

Start with the [Developer Guide](/developer-guide/). It walks you through running a local Homeserver, installing the SDK, and building a first app that signs a user in and reads and writes their data. It ends with the [app templates](https://pubky.github.io/pubky-app-templates/), a working project to grow from.

Share what you build on [pubky.app](https://pubky.app/) and tag the post with [`pubky-apps`](https://pubky.app/search?tags=pubky-apps), so other builders can find it. Apps ready for others to use can be listed under [Community Projects](/resources/#community-projects).

## Get help

For help or feedback, post on [pubky.app](https://pubky.app/) with the tag [`pubky-support`](https://pubky.app/search?tags=pubky-support) or [`pubky-feedback`](https://pubky.app/search?tags=pubky-feedback). The team and community members watch those tags. You can also ask in [Telegram](https://t.me/pubkychat).

## Report bugs and request features

Each component has its own repository, so file issues where the problem occurs; the [Core Repositories](/resources/#core-repositories) list shows which is which. If you are unsure, post on pubky.app with the tag [`pubky-support`](https://pubky.app/search?tags=pubky-support).

Search existing issues first, and comment on a match rather than opening a duplicate. A good bug report lets a maintainer reproduce the problem without guessing:

- The software version and your platform or browser.
- The steps you took, in order.
- What you expected and what happened instead.
- Error messages or logs, as text rather than screenshots.

For a feature request, describe the problem you are solving and how you would use the feature, not only the change you have in mind. An existing feature may already cover your case.

## Contributing to our repositories

Code contributions to our repositories are welcome once the change has been discussed with the team. Open an issue or post on pubky.app describing the problem and your proposed approach before writing code, so the work is not wasted on a direction the team cannot take.

If you use AI tools, you remain responsible for the result. Review and understand every change you submit, and be ready to explain it; unreviewed bulk submissions are closed without review.

## Security

If you believe you have found a vulnerability, follow the [Pubky Security Policy](https://github.com/pubky/.github/blob/main/SECURITY.md) to report it privately instead of opening a public issue.
