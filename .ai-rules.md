# Project Rules

## Documentation Maintenance

When adding or updating documentation:

1. **Link to maintained sources instead of duplicating them** — If a README, docs folder, API reference, release page, or other maintained source exists for a project, library, or tool, link to that source rather than copying install steps, configuration details, feature lists, API behavior, storage layouts, or other information likely to drift.

2. **Keep local docs scoped to their purpose** — Include only the context needed by the reader of the current page. For example, consumer-facing library docs should focus on supported workflows, public contracts, and practical usage, not deep implementation details unless those details directly affect consumers.

3. **Summarize only what belongs here** — It is fine to provide a short, stable summary when it helps orient the reader, but avoid maintaining a second copy of detailed upstream documentation. Prefer "what this means in Pubky" locally and "how to operate or implement it" via links to the maintained source.

4. **Search before expanding docs** — Before introducing technical details, check whether the repo or upstream project already maintains that information. If it does, link to it and keep this knowledge base concise.

## Design Token Usage

This project uses design tokens defined as CSS variables in `src/styles/custom.css`. When implementing any UI from Figma:

1. **Always use CSS variables** — never hardcode spacing, border-radius, font-size, line-height, color, or shadow values. Use the corresponding `var(--token-name)` from `src/styles/custom.css`.

2. **Token mapping from Figma** — Figma uses tokens like `--spacing/5` (with slash). In CSS, we use `--spacing-5` (with dash). Always translate Figma token names to their CSS variable equivalents.

3. **Available token categories:**
   - Spacing: `--spacing-1` (4px) through `--spacing-20` (80px)
   - Border radius: `--radius-sm` (6px), `--radius-md` (8px), `--radius-lg` (12px), `--radius-xl` (16px), `--radius-full` (9999px)
   - Typography: `--text-{size}-size` and `--text-{size}-lh` (e.g., `--text-sm-size: 14px`, `--text-sm-lh: 20px`)
   - Colors: `--base-background`, `--base-foreground`, `--base-card`, `--base-border`, `--base-muted`, `--base-muted-foreground`, `--base-secondary`, `--base-secondary-foreground`
   - Alpha colors: `--alpha-white-16`, `--alpha-white-5`
   - Shadows: `--shadow-xs`, `--shadow-sm`

4. **If a Figma value doesn't have a matching token**, add a new CSS variable to `src/styles/custom.css` under the design tokens section first, then use it.

5. **Comment the Figma source** — add a brief comment above CSS rules referencing the Figma property (e.g., `/* Figma: p spacing-4(16), gap spacing-2(8) */`).

## Animations & Interactions

Figma does not define animations or transitions. When implementing interactive elements (e.g., arrows, buttons, links inside cards), always add appropriate hover/transition animations (fade-in/out, slide, scale, etc.) even if not explicitly shown in the Figma design. Do not leave interactive elements static.

## Accessibility (WCAG 2.1 AA)

When creating or modifying UI components, always ensure:

1. **Focus styles** — All interactive elements must have visible `:focus-visible` outlines. Global styles are in `custom.css`.
2. **External links** — Links with `target="_blank"` must include `aria-label` with "(opens in new tab)" for screen readers.
3. **ARIA roles** — Tab interfaces need `role="tablist"`, `role="tab"`, and `aria-selected`. Toggle state in JS when switching tabs.
4. **Decorative elements** — Add `aria-hidden="true"` to decorative icons/SVGs that convey no meaning.
5. **Touch targets** — Interactive elements must be at least 44×44px. Use padding to expand small visual elements.
6. **Live regions** — Transient feedback (e.g., "Copied!") must use `aria-live="polite"` or update `aria-label` so screen readers announce the change.
7. **Alt text** — Meaningful images need descriptive `alt`; decorative images need `alt=""` with `aria-hidden="true"`.

## Starlight Overrides

This is an Astro Starlight documentation site. Custom components override Starlight defaults via `astro.config.mjs` → `components`. When Starlight injects unwanted styles (e.g., `.sl-markdown-content` spacing rules), use the `not-content` class to opt out — do not fight Starlight's CSS with specificity hacks.

## SVG Icons

Never create SVG icon markup as inline variables or generate SVG code manually. Always download SVG icons from the Figma design file using the Figma MCP tools and save them to `public/images/icons/`.

## Static Assets

All static images and assets are stored in `public/images/`. Background images use the `bg-` prefix (e.g., `bg-square.png`).

## Working Efficiently (AI guardrails)

These rules exist because past sessions burned 100k+ tokens on single-line CSS fixes. Read before starting any layout work.

### 1. Debugging workflow (in order — stop when fixed)

1. **Check computed styles in browser devtools first.** Get actual width, padding, position, and the parent containing block from the live page. Do not mental-model the cascade.
2. **If devtools aren't available**, add `outline: 2px solid red` to the suspect element + its parents in a single test, screenshot once, identify bounds, then move on. Do not loop pixel-scanning.
3. **If 2–3 reasonable CSS attempts don't fix it: STOP and re-isolate.** Toggle off recent changes one at a time to find which one introduced the regression. Do not stack new rules on top of broken ones.

### 2. Layout invariants for this project

- `.install-section` uses `width: 100vw` + `margin-left: calc(50% - 50vw)` to break out of the content panel's `--sl-content-pad-x` on mobile. Changing this affects sibling layout downstream.
- `.home-content` is inside `.content-panel`, which applies `padding: 1.5rem var(--sl-content-pad-x)` (24px on mobile). Siblings (`install-section` vs `home-content`) must agree on whether to break out — mixing them creates asymmetric layout.
- When mobile-overriding a desktop grid/flex container, override `display`, `grid-template-columns`, AND `align-items` together. Leaving desktop `align-items: center` on a switched-to-flex-column causes children to size to content instead of stretching.

### 3. Token-cost guardrails

- **Don't screenshot an 11,000px page repeatedly.** Capture once, then keep editing CSS against the same render until the result is structurally different.
- **Don't pixel-scan PNGs to verify alignment.** That's a sign the wrong tool is in use — switch to devtools or a smaller targeted test page.
- **If a fix burns more than ~3 iterations, the diagnosis is wrong, not the CSS.** Pause and ask the user for a devtools screenshot or a computed-style dump.
- **Read only what you need.** Grep for the target selector and read its block — don't read entire component files just to change one rule.
- **Don't re-fetch Figma metadata for the whole page.** `get_design_context` on the target node already returns the position and tokens you need.

### 4. Figma → CSS translation gotchas (project-specific)

Figma uses page-level absolute positioning (e.g., bg at `x=0, y=608` inside the 390-wide viewport). CSS uses component-scoped relative positioning. When a Figma element visually crosses component boundaries, decide upfront:

- (a) break out via `100vw` + negative margin,
- (b) move the element to a higher parent in the DOM, or
- (c) clip via `clip-path` overhang.

Pick one and commit. Do not iterate between approaches — that's where the token spend explodes.
